二、项目概述

2.1 核心任务

输入 ShapeNet 物体的含噪点云 noisy.npy（形状 (N,3)），输出去噪后的点云 denoised.npy（形状必须仍为 (N,3)，与输入点数严格一致）。评测按百分制：

cd_score  = clamp(100 × (1 − CD_pred  / CD_noisy ), 0, 100)
p2s_score = clamp(100 × (1 − P2S_pred / P2S_noisy), 0, 100)
最终得分  = 0.5 × mean(cd_score) + 0.5 × mean(p2s_score)

即模型必须同时把点云拉回真实表面（P2S）并保持整体分布不塌陷（CD）。

2.2 解决思路与模型选型

我们选用 ASDN（"You Should Learn to Stop Denoising on Point Clouds in Advance"）作为基础方法， 并将其完整移植到 Jittor。选它的理由是：点云各处的噪声强度并不均匀， 平坦区域轻噪、细节区域重噪，用统一深度的网络去噪必然在"欠平滑"和"过平滑"之间二选一。 ASDN 的核心思想是让网络提前决定该在第几层停止去噪——先估计局部噪声强度， 再据此自适应地决定编解码器展开的层数。这正好对应本赛题的评分结构： 过度平滑会破坏 CD，欠平滑会拖累 P2S。

整体流程分三步：

  1. 噪声强度估计（ScaleNet）：DGCNN 风格的 4 层 EdgeConv 网络，全局池化后回归一个标量 ρ —— 含噪 patch 与干净 patch 的体素密度熵之比。熵比越大表示噪声越重。
  2. 自适应深度去噪（FeatureExtraction）：由 ρ 计算展开层数 n = ceil(L − (L−1)·log(γ·ρ + 1))（L=4，γ=0.396），得到 2 / 3 / 4 三档。 同一个 batch 内不同 patch 走不同深度：深度不足的 patch 在第 3、第 4 个编码块处提前退出， 解码端对称地只走对应层数，最后由 3 层 MLP + tanh 输出每点位移场 Δp。
  3. Patch 化推理与拼接：整云过大无法一次前向，按 FPS 种子切成 1000 点的 patch 分别去噪， 再按权重把每个原始点的坐标从"覆盖它最好的那个 patch"取回。

2.3 算法要点与我们的改动

要点说明
全 Jittor 实现 原实现依赖 PyTorch-Lightning、pytorch3d、torch_geometric、torch_cluster，以及两个需要编译的 CUDA 扩展（pointops、Chamfer3D）。本项目把这些全部用纯 Jittor 张量运算重写 （models/pointops_jt.py、models/InfoCD.py、models/dynamic_edge_conv.py）， 无需任何编译步骤，也不安装 PyTorch。
ScaleNet 合规重训 原论文提供的 classify.ckpt 是在其自有数据集上训练的，属于外部预训练权重。 为满足赛题"不得使用外部数据"的规定，我们用 train_classifier_on_starter.py 在赛方训练集上从零重训 ScaleNet；models/feature.py 中不存在任何加载外部权重的代码路径。
训练数据分布对齐 bridge/data_bridge.py 严格复刻测试集的生成方式：网格表面均匀采样 32768 点 → 归一化到单位球 → 叠加拉普拉斯噪声（σ 在 [0.005, 0.02] 均匀采样）→ 以随机种子点 KNN 取 1000 点 patch。 训练时额外加入随机旋转与随机缩放增强。
InfoCD 损失 在双向 Chamfer 最近邻距离上做 InfoNCE 式对数归一化，相比朴素 CD 对离群点更稳健， 缓解了"少数噪点主导梯度"的问题。
多轮迭代去噪 把整套 patch 化去噪重复 niters 次。本地消融显示 niters=2 最优； niters=3 因过度平滑反而下降（见 5.5）。
无 GT 本地验证 测试集没有 GT，为避免把每日提交次数消耗在盲猜上，我们用 tools/make_eval_set.py 从训练集另建了一个 30 样本的带 GT 验证集，并用 tools/evaluate.py 复现赛题评分公式， 所有超参决策都在这个集合上完成。

三、代码结构说明

3.1 复现主链路（code/ 根目录）

只想快速复现的话，看这一行就够了：bash run_all.sh infer（用随包权重直接生成 提交文件）或 bash run_all.sh train（从零训练后再推理）。 本项目只有 4 个入口脚本，即下表的 ①②③④，其余文件都是被它们 import 的模块或 tools/ 下的本地分析工具，无需单独运行。
文件功能
run_all.sh 一键复现入口。infer 模式按 A 榜最优配置直接推理并打包； train 模式先跑完 ①②，再跑 ③④。脚本会检查数据布局， 并在 datalist/ 缺失时自动调用 make_datalist.py 重建。
train_classifier_on_starter.py ① 训练 ScaleNet 噪声强度分类器。构造 Classify，用 get_supervised_loss_nn（预测熵比 vs 真实熵比的 MSE，sum 归约）+ Adam 优化， 每 5 个 epoch 存一个 experiments/classify/classify-epochXXX.pkl。
train_on_starter.py ② 训练 ASDN 去噪主网络。构造 DenoiseNetCD（内部按 --classify_ckpt 载入 第 ① 步的 ScaleNet），按 InfoCD 损失训练，逐 epoch 把平均损失写入 experiments/asdn/train_log.csv，每 5 个 epoch 存一次权重。 脚本按 jt.rank 做了主进程判断，可直接用 mpirun 多卡运行。
predict_on_starter.py ③ 推理并写出赛题提交格式。逐样本读 noisy.npy → 归一化到单位球（记录 center/scale）→ 调用 patch_based_denoise 迭代 --niters 次 → 反归一化回原坐标系 → 存 <out_root>/shapenet/<synset>/<model_id>/denoised.npy（float32）。
check_submission.py ④ 打包前自检：逐条核对预测文件是否存在、点数与 noisy.npy 是否一致、有无 NaN/Inf、 坐标量级是否异常。前两项曾是导致提交得 0 分的直接原因，务必在打包前运行。
make_datalist.py 扫描数据目录重建 datalist/*.txt（官方 starter code 亦自带该目录）。

3.2 模型定义（code/models/）

文件关键内容
denoiseCD.py DenoiseNetCD。get_supervised_loss：patch 减去种子坐标后前向得位移场， 与干净 patch 算 InfoCD。patch_based_denoise：FPS 取 seed_k·N/patch_size 个种子 → KNN 取 patch → 分批前向 → 按 exp(−归一化距离) 的最大权重决定每个原始点归属哪个 patch，完成拼接。
feature.py FeatureExtraction：编码器 = StartBlock + 4×Downsampling， 解码器 = 4×Upsampling。前向时先用 ScaleNet 得到每个 patch 的 ρ， 换算成 2/3/4 档层数，把同档的 patch 分组后按组提前退出／继续下探，最后 3 层 MLP + tanh 输出位移。
blocks.py Downsampling = MRE（两级 RFE 局部注意力聚合，16 邻居）+ FPS 下采样； Upsampling = 反距离加权插值（k=8）+ 交叉注意力 Point Transformer 层（16 邻居）+ 与编码器同层特征跳连的 MLP。
classifyNet.py ScaleNet：4 层 DynamicEdgeConv（3→16→24→72，拼接 112→256）， 全局平均池化 + 3 层 MLP + tanh。get_edge_index 取 k+1 近邻并丢弃第 0 个（自身）实现自环剔除。
classify.py Classify：封装 ScaleNet，提供熵比回归的监督损失。
dynamic_edge_conv.py EdgeConv：out_i = MLP_lin(x_i) + max_j MLP([x_i, x_j − x_i])。 用稠密 (B,N,k,C) 邻居张量 + jt.max 实现，替代 torch_geometric 的稀疏消息传递。
InfoCD.py chamfer_dist（纯 Jittor，返回值与 Chamfer3D 扩展一致）与 calc_cd_like_InfoV2。
pointops_jt.py 纯 Jittor 的 furthestsampling / queryandgroup / interpolation （保持原 CUDA 扩展的 offset 格式 API）以及 knn_points / farthest_point_sampling。 均为精确暴力实现，行为与原算子等价。
utils.py get_entropy_B：体素密度熵（动态体素尺寸、唯一体素计数、10 桶直方图）， 用于构造 ScaleNet 的监督目标。

3.3 数据处理（code/bridge/）与工具（code/tools/）

文件功能
bridge/data_bridge.py ShapeNetPatchTrainDataset：每次 __getitem__ 产出一组 (含噪 patch, 干净 patch, 种子点, 噪声 σ)，即训练损失所需的全部输入。 ShapeNetNoisyPredictDataset：推理时产出整片含噪点云及其相对路径。 两者均继承 jittor.dataset.Dataset（数据集自带批处理）。
tools/evaluate.py 按赛题公式计算 CD / P2S 与总分；P2S 优先用 point-cloud-utils 的 BVH 精确求解。
tools/make_eval_set.py 从训练集构造带 GT 的本地验证集（clean / noisy / 同变换归一化后的网格三件套）。
tools/analysis.py 逐样本得分统计：按类别、按噪声档分组，列出最好／最差样本。
tools/estimate_noise.py 无 GT 的噪声强度估计（局部 PCA 平面拟合残差 RMS），用于验证"噪声自适应"的可行性。
tools/visualize_errors.py、tools/plot_loss.py 误差着色的交互式可视化（Plotly HTML）与训练损失曲线。
tools/results/*.csv 上述工具产出的记录，含 niters=1/2/3 的逐样本得分，即 5.5 节消融结论的原始数据。

注：tools/ 下的脚本只用于本地验证与分析，不参与 A 榜结果的生成； A 榜结果完全由 3.1 节的 ①②③ 三个脚本产生。

六、其他补充

6.1 合规性说明

  • 未使用测试集标签。测试集不含 GT，代码中也没有任何读取测试集 GT 的路径。 predict_on_starter.py 只读 noisy.npy；check_submission.py 读 noisy.npy 仅用于核对点数。用于调参的本地验证集完全由 训练集重新采样加噪构造（tools/make_eval_set.py），与测试集无交集。
  • 未使用外部数据或外部预训练权重。ScaleNet 与去噪网络均在赛方提供的 ShapeNet 训练集上从零训练。原论文发布的 ASDN.ckpt / classify.ckpt 在项目早期曾被下载用于对照，但提交代码中不存在任何加载它们的代码路径—— models/feature.py 只会新建 ScaleNet，或加载由 train_classifier_on_starter.py 训练出的 Jittor .pkl。
  • 与 A 榜的一致性。提交代码相对 A 榜跑分时的工作目录，仅删除了从未被调用的死代码 （原论文面向 PUNet 数据集的 train_ASDN.py / train_classifier.py / test_ASDN.py 及其专属依赖 utils/；这三个脚本引用了本仓库中并不存在的 datasets.pcl、datasets.patch、Evaluate 模块，本就无法运行）， 并把本地分析脚本归入 tools/。 模型定义、超参数、数据处理逻辑均未做任何改动，结果不受影响。

6.2 复现注意事项

  • 点数必须一致。评测按 (N,3) 逐样本比对，输出点数与 noisy.npy 不同会直接得 0 分。 我们早期的两次提交正是栽在这里，因此加入了 check_submission.py，打包前请务必运行。
  • 必须反归一化。网络在单位球坐标系下工作，predict_on_starter.py 会用记录的 center/scale 把结果还原到原坐标系。若跳过这一步，CD/P2S 同样会归零。
  • 显存不足时调大 --seed_k_alpha（减小单批 patch 数），或调小 --batch_size。 patch_based_denoise 中有断言 patch_step > 0，若触发说明 seed_k_alpha 相对点数过大，需调小。
  • 速度。KNN 与 FPS 是精确暴力实现（无自定义 CUDA kernel），结果正确但比原 CUDA 扩展慢； 大点云上的推理耗时以此为主。
  • 随机性。训练数据每个 epoch 重新采样表面点、重新加噪，随机种子固定为 2024 （jt.set_global_seed + np.random.seed）。GPU 上的浮点归约顺序不保证逐位可复现， 重训得到的分数可能有小幅波动。

6.3 已知问题

  • models/classifyNet.py 的自环剔除假设"每个点的最近邻是它自己"， 当点云中存在完全重合的点时会误剔除一个真实邻居；实测对结果无可观测影响。
  • tools/evaluate.py 在未安装 point-cloud-utils 时会退化为 "点到网格顶点"的近似 P2S，绝对数值偏大（相对排序仍然可用）。安装后走 BVH 精确计算。
  • Jittor 与 PyTorch 的 BatchNorm momentum 定义等默认设置略有差异， 与原 PyTorch 实现做逐位数值对比时会有小幅漂移。
